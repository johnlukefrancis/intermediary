# Changelog

## 0.1.20 — 2026-09-05

_0.1.19 was never tagged; it ships here together with the follow-up polish below. This is also the first published GitHub release since 0.1.11 — 0.1.12 through 0.1.19 were built and installed locally._

- Source Control polish: the CHANGES header's bulk actions (discard-all, stage-all) are right-aligned in the section header, and the Discard All confirm modal is compacted to the tracked/untracked counts.

## 0.1.19 — 2026-09-04

- Added a Discard All button to the SOURCE rail: the CHANGES section header now carries a discard glyph beside stage-all (VS Code's placement). It opens a destructive confirm modal naming only the counts (tracked restored from the index, untracked deleted) so the modal stays small at any change count, then sends one batched discard whose targets carry the same per-file stamps the row action sends, so a file changed since review is refused rather than destroyed. Disabled while an action is pending, status is truncated, or CHANGES is empty.

## 0.1.18 — 2026-09-04

_0.1.16 and 0.1.17 were built and installed locally as terminal acceptance candidates; the accepted terminal ships as 0.1.18._

- Added an integrated terminal as the third rail section, TERMINAL, beside ZIPS and SOURCE (a fourth section on handset). Each tab is JL's own PowerShell 7 with its profile loaded, hosted over ConPTY inside the Tauri process, so `claude`, `codex`, `wsl`, and `wb-code` run inside the app with their TUIs rendering and reflowing. Host-rooted repos start in their folder; native WSL roots are preflighted in one pinned distro before pwsh loads the profile and runs `wsl.exe -d <distro> --cd '<repo>'`, landing in bash inside the repo. Sessions are grouped per repo; every retained tab counts toward the twelve-tab app bound, survives rail, repo-tab, handset, and mode switches by being parked off-screen rather than disposed, and does not persist across restarts. Keys follow Windows Terminal (Ctrl+Shift+C/V, Ctrl+C copies a selection, Ctrl+V and right-click paste, Shift+Enter sends a newline for Claude Code); paste reads the clipboard in Rust because WebView2 blocks the page-side read. Closing a tab is console-first with a Job Object as the bounded escalation, so pwsh, `wsl.exe`, and conhost end while GUI apps launched from the shell survive; at app exit every admitted transaction reaches its joined receipt before the agent supervisor runs, so an in-app `wsl` session never keeps the distro alive at the idle probe (ADR-013 rule 4). Output is cumulative-credit-gated so a flood stays responsive, a lost acknowledgement is retried, and a minimized window never stalls a command. Colours come from new `--terminal-*` deck-token slots that follow the tab accent; the bar cursor is two pixels wide, and `> STARTING PWSH` stays up until the shell paints its first prompt (a profile can take seconds; keys typed meanwhile reach the shell). A drag divider between Auto Files and the rail now sets the rail's width for all three sections (persisted `uiState.railWidthPercent`, default 35 %, double-click resets). The whole surface is Tauri IPC (six app commands and one raw-byte channel per session): no agent, no shell or clipboard plugin, no CSP or capability change (ADR-010 clause 7). Contract in `docs/design/terminal_design.md` and `docs/architecture/terminal_architecture.md`; witness route in `docs/commands/verify_terminal.md`.
- **Terminal promotion-review closure:** rebuilt the Rust owner as an atomically admitted transaction retained through Opening, Running, Closing, Reaping, and a joined final receipt; app exit now freezes admission and waits process, reader, waiter, and PTY teardown before the agent supervisor's WSL idle decision. Native WSL roots are proved in one pinned distro through the shared bounded non-login stdin-script boundary before ConPTY opens, and a later entry failure exits PowerShell instead of falling back to its profile directory. Explicit close detaches the webview sink before privately draining output; cumulative sent/consumed watermarks make lost, duplicate, and reordered acknowledgements recoverable. The Windows adapter now places ConPTY and the Job Object in the same `CreateProcessW` attribute list, so profile code cannot run outside process-tree ownership. Forced cleanup arms kill-on-close and observes the Job only within a real deadline; an unproved receipt remains owned for app-exit retry and prevents the WSL idle route. All retained xterm/WebGL tabs—including exited and failed tabs—count toward twelve, and rebinding a repo id to a different root closes its old group at both lifecycle and restart boundaries. Focused owner tests cover atomic capacity, opening-versus-exit, cumulative credit, close-time detach, joined teardown, unresolved-tree finality, and native Windows Job membership. The native xterm scrollbar now keeps its full drag target while exposing the repo accent on a visible track and adding the established accent glow on hover and drag, so long scrollback is practical to drag as well as wheel-scroll.
- Fixed the right rail forgetting its section across restarts: the Rust config mirror (`UiState`) had no `active_rail` field, so every save round-trip dropped `uiState.activeRail` and the rail always reloaded on ZIPS. The field is now mirrored and validated (`zips` / `source` / `terminal`), and the frontend schema falls back to ZIPS on an unknown value instead of locking persistence.
- Fixed the Windows installer build running against stale dependencies: `run_windows_tauri_task.ps1` only ran `pnpm install` when the mirror's `node_modules` was absent, and the WSL sync excludes `node_modules`, so a lockfile change in WSL (new packages) never reached the mirror and the build failed mid-run. The script now installs with `--frozen-lockfile` whenever `node_modules` is missing or older than the synced `pnpm-lock.yaml`.

## 0.1.15 — 2026-09-04

_0.1.14 was built and installed locally on 2026-09-03 but never tagged; everything below ships as 0.1.15._

- A failed push or pull whose effect the agent cannot prove (a remote rejection, a timeout) now shows Git's own message as a `PUSH DID NOT FINISH` / `PULL DID NOT FINISH` notice while the column reconciles, instead of silently returning to the previous counts.
- **ZIPS write-surface review closure (2026-09-04):** answered `docs/reports/zips_tree_write_surface_review_20260904.md`. `.git` is never listed, never listable, and never an import destination or a nested source (the drop is refused whole); Replace now carries the reviewed conflict list (`onConflict: { replace: [...] }`) and the agent refuses again with a fresh list if any other collision appeared, writing authorized destinations with a replacing primitive and everything else with `create_new` / `rename_no_replace`; move under refuse and rename use the non-replacing rename (case-only renames excepted; drvfs through the WSL agent is refused with `SOURCE_CONTROL_UNSUPPORTED_LAYOUT`); a quarantine directory this agent process created is never removed by its own sweep, so a deleted entry's recovery copy survives until the next agent start as promised; and pending Replace/delete/rename state plus the commit-message draft reset when the active repo changes, so a confirmation can never apply to a different repo. The surface's contract now lives in `docs/design/zips_tree_write_surface_design.md`.
- ZIPS tree selection and worktree actions (2026-09-04): rows select with click / Ctrl / Shift (a plain folder click also toggles expansion; the checkbox alone controls bundle inclusion), the tree has a keyboard map (arrows, Enter, Delete, F2, Ctrl+X/C/V, Escape), and files and folders can be cut/copied/pasted, deleted into the repo's discard quarantine (recoverable until the next agent start), moved by dragging within the tree (with the same hover-to-expand as the OS drop), and renamed inline. One new `worktreeAction` command runs every action in the root-owning agent under the Source Control mutation lock; folder-over-folder moves are refused rather than merged, `.git` is never touched, and the import's conflict codes were renamed to the shared `ENTRY_CONFLICT` / `ENTRY_KIND_MISMATCH`. Opening or closing a file in the shared workspace no longer remounts the right rail (one desktop shell now hosts both states), so the ZIPS tree keeps its expansion and selection; the tree also opts out of native text selection so Shift-click and row drags no longer highlight names.
- Added drag-in import: OS files or folders dropped from Chrome or Explorer onto the ZIPS explorer tree are copied into the targeted repository folder by the agent that owns the root (new `importFiles` command, run under the Source Control mutation lock, with Windows→WSL path translation for WSL roots). Hovering a collapsed directory for about 700 ms during the drag expands it; existing names are refused and confirmed through a Replace modal; nothing is staged in Git, and the imported files surface through the ordinary watcher events. The main window now enables Tauri's native drag-drop (drag-out is pointer-driven and unaffected). The ZIPS tree also keeps its expansion across topology refreshes now (a root-level drop or a save-by-rename no longer collapses it); only switching repos resets it.
- Added Source Control to the right rail (`[ ZIPS ] [ SOURCE n ]`, also a third handset section): branch, upstream, and ahead/behind status; STAGED CHANGES / CHANGES / MERGE CHANGES sections with per-row and per-section stage and unstage; commit box with Ctrl+Enter; per-file discard behind a confirm; read-only staged/worktree diffs in the shared workspace; pull (fast-forward only) and push. Git runs in the agent that owns the repo root, so WSL and Windows repos both work without leaving the app.
- The repo watcher now emits a coalesced `sourceControlChanged` event for Git metadata writes (including linked worktrees' real git dir) and working-tree changes, so external commits refresh the view without polling; topology refresh no longer fires for writes inside `.git`.
- Promoted the bounded Git runner, porcelain parser, and repo-prefix capture behind a public `im_bundle::git` facade shared by bundle evidence and source control; the runner now keeps stderr/stdout for actionable errors and stops mutations gracefully on timeout, naming any leftover `.git/index.lock` it can see rather than guaranteeing it never occurs.
- Host agent source-control commands are dispatched without holding the runtime write lock, and the two duplicated repo-id routing tables were replaced by one exhaustive `UiCommand::repo_id()`.
- Fixed `pnpm` 11 build-script approval (`pnpm-workspace.yaml`) so `pnpm exec` works again in WSL.
- ZIPS file explorer rows now carry Git-status decorations when the active repo has a changed working tree: changed files get a tinted name and change-letter badge, directories get a tinted name and a count of distinct changed paths beneath them (colored by the worst change beneath), and expanded directories re-list in place on `sourceControlChanged` so a newly created file appears with its badge without collapsing the tree.
- The right-rail `DeckSectionSwitcher` is now a segmented icon rocker (archive-box ZIPS / git-branch SOURCE, plus a stacked-documents FILES cell on handset) instead of the bracket text tabs; the SOURCE count sits beside its glyph and the section name remains the accessible name and tooltip.
- Merge conflicts are now impossible to miss: the SOURCE rocker cell turns into a pulsing error-toned alert showing the conflict count, the column leads with a conflict banner and the MERGE CONFLICTS section (renamed from MERGE CHANGES) ahead of staged/unstaged changes, COMMIT is disabled with a resolve hint while unmerged paths exist (the agent now refuses such commits with `GIT_UNMERGED_PATHS`, and `status.omitted.unmergedOutsideRoot` counts conflicts above a subdirectory-rooted entry so the alert fires even when no row can be listed), and a conflict diff opens with a `MERGE CONFLICT` subtitle, a pinned notice counting unresolved blocks (truncation- and binary-aware), and highlighted `<<<<<<<` / `=======` / `>>>>>>>` marker lines.
- A changed image opened from SOURCE now shows a side-by-side image diff instead of `BINARY FILE`: two panes labelled with the plain word plus the Git term (`PREVIOUS · HEAD` / `CURRENT · INDEX` staged, `PREVIOUS · INDEX` / `CURRENT · WORKTREE` unstaged, `NEW` / `DELETED` slots, `OURS` / `THEIRS` for conflicts), each footer showing dimensions and bytes, transparency reading on a checkerboard, and panes stacking on handset; the agent reads each side with `git show` or the worktree reader, bounded at 12 MiB per side and flagged `truncated` rather than failing, with a missing side reported as `null`. Non-image binaries are unaffected and still show `BINARY FILE`.
- **Adversarial-review hardening (2026-09-03):** fixed the P0/P1 findings from `docs/reports/source_control_adversarial_review_20260903.md` — copy/rename rows carry both endpoints instead of a flattened path bag, so discarding a copy no longer erases the source's own edits; commit and discard are bound to the snapshot the user reviewed (an index-tree identity then, per-target stamps) and refuse with `SOURCE_CONTROL_STATE_CHANGED` when Git state moved underneath them; the agent drains in-flight mutations on `shutdown`/SIGTERM and the Tauri supervisor asks before it kills; the runner bounds its post-exit pipe drain instead of waiting on inherited pipes forever; mutation locks key on the physical git dir instead of the UI repo id; stage-all/unstage-all enumerate the section from a fresh status instead of pathspec `.`, and `committable` now requires no unmerged records; the watcher tracks Git-tracked paths so they refresh even under `node_modules`/`target`; the corrected timeout ladder is agent 20/60/120/180 s, host→WSL 120/280/340/380/420 s, UI 150/310/370/410/450 s, with discard as its own class. See `docs/architecture/source_control_architecture.md` and `docs/design/source_control_design.md` for the full contract.
- **Fix-layer closure hardening (2026-09-03):** answered the two P0 ownership defects from `docs/reports/source_control_fix_layer_review_20260903.md` — the reviewed snapshot now owns the mutation, not just its preflight, and shutdown no longer exits while a mutation is still active. Status retries a torn index-identity read up to 3 times, falling back to an empty `indexTreeSha` rather than pairing a stale list with a newer identity. Discard claims each existing target into an operation-owned quarantine directory and verifies bytes plus millisecond-and-nanosecond mtime before touching it, honours `expectedMissing` so a file recreated after being missing at review is never overwritten, and reports `effect: unknown` (never `notApplied`) after any partial batch failure. Shutdown no longer schedules an exit on `drained: false`: both agents wait up to a 450 s emergency bound before owning and terminating their process tree, the host treats an unavailable WSL backend as drained only with no outstanding forwarded mutation, and the Tauri supervisor waits up to 480 s for an explicit `drained: true` ack (never labelling a disappeared process `drained`) and skips WSL distro termination while finality is unknown. On Windows the Git runner's children run inside a Job Object so a forced stop takes hooks and helpers with it instead of leaving them detached.
- **Third-review hardening (2026-09-03):** answered `docs/reports/source_control_hardening_review_20260903.md`. A commit is now bound to one reviewed-snapshot identity — `status.snapshotId`, a hash over the branch (or `detached`), HEAD, the index tree, and the contents of `MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD` — so a same-tree commit on another branch, or the same index with a different merge in progress, is refused like any other move; the wire is `commit { message, expectedSnapshotId }`, and a status with no stable snapshot disables COMMIT instead of committing unchecked. The post-commit retraction is gone: a commit Git published stands, and the result reports what a hook did to it — `hookChangedPaths` for reviewed paths it rewrote (informational) and `hookAddedPaths` for paths nobody reviewed (a warning notice naming them and pointing at a soft reset). Discard keeps a discarded file's bytes: a target moves through `claimed` → `verified` → `retained` and stays until the next agent start's sweep, which removes only directories whose `verified` marker proves the destruction was authorized and holds everything else. Rollback and put-back use a new `im_bundle::fs_atomic::rename_no_replace` (Linux `renameat2`, Windows `MoveFileExW`) and never replace what is at the destination; bytes that cannot be returned are held as `unrestored` with an unknown effect. A present path the review could not stamp is refused rather than discarded blind, and a worktree on a different volume from its repository is refused with the new `SOURCE_CONTROL_UNSUPPORTED_LAYOUT`. The Tauri supervisor now spawns the host agent into a supervisor-owned Windows Job Object and terminates it on the emergency kill path; a Git mutation that cannot be given a job is refused before it spawns, and the host agent's ledger of forwarded WSL mutations untracks confirmed errors at the decode site so a refusal can no longer hold a shutdown open. Rejected findings — a private commit transaction with hooks inside it, per-status content digests, and the `git restore` TOCTOU window among them — are recorded as accepted boundaries in `docs/design/source_control_design.md` rather than left open. Both Windows job objects (per Git command and around the host agent) are cross-compiled but not yet exercised at runtime; `docs/known_issues.md` carries that.

## 0.1.13 — 2026-09-01

- When a bundle Git patch that includes deleted-file bodies exceeds an 8 MiB reviewable budget (or the 32 MiB hard bound), capture now retries with header-only deletions (`--irreversible-delete`) instead of shipping a truncated or deletion-dominated patch, records `patchDeletions: headerOnly` in the manifest, and says so in `BUNDLE_GIT_STATUS.txt`. Ordinary patches keep full deletion bodies.
- Bundle format 3: added `BUNDLE_GIT_INDEX_DIFF.patch` (HEAD to index) and `BUNDLE_GIT_WORKTREE_DIFF.patch` (index to working tree) beside the combined patch, plus `candidateIndexTreeSha` in the manifest, computed read-only and equal to what `git write-tree` would return, so a reviewer can tell staged from unstaged and later match a commit to the reviewed index.
- Added `BUNDLE_GIT_OMITTED_PATHS.txt` naming every changed repository path the selection left out with its status and the exclusion rule; content of those paths stays out of the bundle.
- Raised the selected diff pathspec budget from 4,096 paths/256 KiB to 16,384 paths/1 MiB so a multi-thousand-file working tree gets a complete patch instead of a `pathLimit` partial.
