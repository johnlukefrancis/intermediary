# Changelog

## 0.1.14 — 2026-09-03

- Added Source Control to the right rail (`[ ZIPS ] [ SOURCE n ]`, also a third handset section): branch, upstream, and ahead/behind status; STAGED CHANGES / CHANGES / MERGE CHANGES sections with per-row and per-section stage and unstage; commit box with Ctrl+Enter; per-file discard behind a confirm; read-only staged/worktree diffs in the shared workspace; pull (fast-forward only) and push. Git runs in the agent that owns the repo root, so WSL and Windows repos both work without leaving the app.
- The repo watcher now emits a coalesced `sourceControlChanged` event for Git metadata writes (including linked worktrees' real git dir) and working-tree changes, so external commits refresh the view without polling; topology refresh no longer fires for writes inside `.git`.
- Promoted the bounded Git runner, porcelain parser, and repo-prefix capture behind a public `im_bundle::git` facade shared by bundle evidence and source control; the runner now keeps stderr/stdout for actionable errors and stops mutations gracefully on timeout, naming any leftover `.git/index.lock` it can see rather than guaranteeing it never occurs.
- Host agent source-control commands are dispatched without holding the runtime write lock, and the two duplicated repo-id routing tables were replaced by one exhaustive `UiCommand::repo_id()`.
- Fixed `pnpm` 11 build-script approval (`pnpm-workspace.yaml`) so `pnpm exec` works again in WSL.
- **Adversarial-review hardening (2026-09-03):** fixed the P0/P1 findings from `docs/reports/source_control_adversarial_review_20260903.md` — copy/rename rows carry both endpoints instead of a flattened path bag, so discarding a copy no longer erases the source's own edits; commit and discard are bound to the snapshot the user reviewed (`expectedIndexTreeSha`, per-target stamps) and refuse with `SOURCE_CONTROL_STATE_CHANGED` when Git state moved underneath them; the agent drains in-flight mutations on `shutdown`/SIGTERM and the Tauri supervisor asks before it kills; the runner bounds its post-exit pipe drain instead of waiting on inherited pipes forever; mutation locks key on the physical git dir instead of the UI repo id; stage-all/unstage-all enumerate the section from a fresh status instead of pathspec `.`, and `committable` now requires no unmerged records; the watcher tracks Git-tracked paths so they refresh even under `node_modules`/`target`; the corrected timeout ladder is agent 20/60/120/180 s, host→WSL 120/280/340/380/420 s, UI 150/310/370/410/450 s, with discard as its own class. See `docs/architecture/source_control_architecture.md` and `docs/design/source_control_design.md` for the full contract.
- **Fix-layer closure hardening (2026-09-03):** closed the two P0 ownership defects from `docs/reports/source_control_fix_layer_review_20260903.md` — the reviewed snapshot now owns the mutation's effect boundary, not just its preflight, and shutdown no longer exits while a mutation is still active. Commit binds to both `expectedIndexTreeSha` and `expectedHeadSha`; after `git commit` runs (hooks included) the agent compares the resulting tree to the reviewed one and accepts a hook's changes only when every changed path was already in the reviewed index list (reported as `hookChangedPaths`), otherwise it retracts the commit (`git update-ref`, CAS-guarded) before it is visible. Status retries a torn index-identity read up to 3 times, falling back to an empty `indexTreeSha` rather than pairing a stale list with a newer identity. Discard claims each existing target into an operation-owned quarantine directory and verifies bytes plus millisecond-and-nanosecond mtime before touching it, honours `expectedMissing` so a file recreated after being missing at review is never overwritten, reports `effect: unknown` (never `notApplied`) after any partial batch failure, and sweeps crash-leftover quarantine directories at agent start. Shutdown no longer schedules an exit on `drained: false`: both agents wait up to a 450 s emergency bound before owning and terminating their process tree, the host treats an unavailable WSL backend as drained only with no outstanding forwarded mutation, and the Tauri supervisor waits up to 480 s for an explicit `drained: true` ack (never labelling a disappeared process `drained`) and skips WSL distro termination while finality is unknown. On Windows, the Git process tree runs inside a Job Object so a forced stop takes hooks and helpers with it instead of leaving them detached — retiring the `docs/known_issues.md` entry for that gap. See `docs/architecture/source_control_architecture.md` and `docs/design/source_control_design.md` for the full contract; both reviews are registered in `docs/guide.md`.

## 0.1.13 — 2026-09-01

- When a bundle Git patch that includes deleted-file bodies exceeds an 8 MiB reviewable budget (or the 32 MiB hard bound), capture now retries with header-only deletions (`--irreversible-delete`) instead of shipping a truncated or deletion-dominated patch, records `patchDeletions: headerOnly` in the manifest, and says so in `BUNDLE_GIT_STATUS.txt`. Ordinary patches keep full deletion bodies.
- Bundle format 3: added `BUNDLE_GIT_INDEX_DIFF.patch` (HEAD to index) and `BUNDLE_GIT_WORKTREE_DIFF.patch` (index to working tree) beside the combined patch, plus `candidateIndexTreeSha` in the manifest, computed read-only and equal to what `git write-tree` would return, so a reviewer can tell staged from unstaged and later match a commit to the reviewed index.
- Added `BUNDLE_GIT_OMITTED_PATHS.txt` naming every changed repository path the selection left out with its status and the exclusion rule; content of those paths stays out of the bundle.
- Raised the selected diff pathspec budget from 4,096 paths/256 KiB to 16,384 paths/1 MiB so a multi-thousand-file working tree gets a complete patch instead of a `pathLimit` partial.

## 0.1.12 — 2026-08-17

- Fixed Windows **Open Containing Folder** actions so project-relative file paths use native separators and Explorer selects the intended file instead of falling back to Desktop or Documents.
